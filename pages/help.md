# Flow-Desk 帮助

这一页存在 `data\help.md`，是一份明文清单。想知道它怎么写、怎么改，往下看第一节；想查某个功能在哪儿，看第二到十四节；改字、装卸组件这些日常操作在第十五到十七节；界面为什么是这个颜色、背景想铺渐变或图片按什么规矩，第十八节。

## 一、这一页怎么改

- 用 Notepad++（或任何文本编辑器）打开 `Flow-Desk\data\help.md`（程序读的就是这一份），改完保存。
- 回 Flow-Desk 再点一次「帮助」，看到的就是新版本。每次点开都重新读文件，不缓存，不用重新构建，也不用重启程序。
- 它是 markdown，但只认这么几种写法，够用也好读：
  - 行首一个 `#` 是大标题，两个 `##`（或三个）是小节标题。
  - 行首 `- ` 是一个条目；行首两个空格再 `- ` 是套在上一条下面的小条目。
  - 一对 `**` 包起来的是加粗，一对反引号包起来的是代码字。
  - 三枚反引号围起来的整块是代码块，块里的字原样摆，一个都不改。
  - 空行分段。除此以外的写法（表格、图片、链接语法）不认识，会当普通段落摆出来。
- 这一页不执行任何脚本：文档里就算写了脚本，也只是几个字。排版颜色全跟着 Flow-Desk 的配色走，不用写样式。
- `pages\help.md` 是出厂那一份，跟着软件更新走。更新换了出厂版、而你改过 `data\` 这一份时，程序一个字不动你的，只在 `data\relocate.txt` 记一行，告诉你去哪儿对出厂版。
- 旧版的帮助是一份网页文件：你的 `data\help.html` 如果改过，程序原样留着不删，但现在读的是 `data\help.md` 这一份。想找回自己写的那几段，自己打开旧文件对过来就行。

## 二、Flow-Desk、为写、声笔输入法练习各是什么

- **Flow-Desk** 是外壳：一张摆插件的桌面，加一套全局配色。它自己不做业务，业务都在组件里。
- **Why Not Write**（为写）是写作工具，**Rime Practice**（声笔输入法练习）是打字练习器。两者都不再是一张独立的页面：代码拼在 Flow-Desk 那一张页里，卡片点一下就在同一个窗口的覆盖层里现开，关掉是把那一层拆干净，不另起窗口、也没有自己的页面文件。
- 两种开法吃的是同一棵目录里的同一批文件：平时跑 Flow-Desk 根上的 Flow-Desk.exe；开发时起那台本地开发服务器，在浏览器里看同一批页面。组件、词库、两份清单读写的都是磁盘上同一份文件，不会出现「那个页面那份是草稿、程序那份才作数」。双击那一份页面用浏览器打开的开法已经废止。

## 三、标题栏和菜单

Flow-Desk 的标题栏是自己画的，跟首页一个配色，系统那条菜单栏和标题栏都去掉了。左上角三横线是菜单，右上角三个按钮是最小化、最大化（还原）、关闭。顶栏空白处能拖着挪窗口。

- 菜单从上到下分四组：重新载入页面、强制重新载入、添加插件、设置；放大、缩小、实际大小、全屏；最小化、最大化或还原、退出程序；帮助文档。
- 快捷键：`Ctrl R` 重新载入，`Ctrl Shift R` 强制重新载入，`Ctrl +` / `Ctrl −` / `Ctrl 0` 缩放，`F11` 全屏，`Ctrl H` 帮助，`Ctrl Q` 退出。
- 窗口没焦点时程序不接任何键，后台全局快捷键已经整个拿掉了（桌面透明层和开发者工具同样已经删掉）。所以在别的软件里按这些键，Flow-Desk 一点反应都不会有，也不存在抢别人快捷键这回事。
- 为写和声笔输入法练习开起来是 Flow-Desk 窗口里的覆盖层，用的是同一个自绘顶栏；封面右上有「关闭」和「重新载入」两颗，重新载入是把这一层拆了原地再开一次。

## 四、卡片

- 「添加插件」开列表，顶上能搜。点一下挂一张卡，按住卡片可以拖，四个角能缩放，格子里自动吸附。卡片右上角那个 `✕` 和拖动把手分开摆着，点关闭不会带着卡片一起飞。
- 卡片标题条上的按钮：`✎` 改代码，`⚙` 设置（这一家在说明书里点明了自己有设置才摆），`词` 改词库，`⛶` 放大视图，`◐` 换配色，`A` 换这一张卡的字体，`✕` 从桌上撤下。面积到页面四分之一，卡片自己进全功能状态。
- `✕` 只是把这张卡从桌上撤走，数据一条不动，随时在「添加插件」里再挂一张。要隐藏它（列表里也不出现）和卸掉它（不再加载这一家），都在「添加插件」那张列表里按；隐藏不删数据，勾上「显示已隐藏」就能找回来。卸掉的是这一家参不参加这一轮加载，桌上一张卡和设置里它自己垫的那几行跟着没了；插件本身留在 `data\plugins\` 里，随时在同一个列表装回来（见第十七节）。要不要顺手清数据，卸的时候勾一下才作数。
- 每张卡摆上桌的默认大小写在 `data\card-size.yaml` 这份清单里，设置 → 数据 → 卡片大小那一行能改（见第十五节）。你亲手拉过大小的卡片保着你拉的样子，清单只管你没动过的。
- 这六家卡都不显示标题条，卡面上直接画东西。鼠标停到卡片上，那几个按钮会在右上角浮出来，不占地方。
- Why Not Write 停靠那一侧的标题条上，「改代码」「设置」「改词库」排在「常驻」左边，和 Flow-Desk 卡上的是同一套东西，两边入口对等。

## 五、改内置插件的代码

内置这六家组件（为写、声笔输入法练习、你的便签、你的句子、日程、音乐遥控器）和导入的第三方包住的是同一层：`data\plugins\<组件id>\`。卡上点 `✎`「改代码」，改的就是这一格里的 `main.js` —— 这一份就是它现在跑的这一份，存了就是新的。

- 存完只重载这一家：加载器把这一份重新读进来，宿主在那儿重画这张卡。不跑构建，也不用刷整页。
- 想回到出厂那一版：点「恢复出厂」，从程序自带的那一层（`resources\app\data\plugins\<组件id>\`）把同一份文件原样拷回来，拷完同样立刻重载。这一家有几份出厂原文，那个按钮上就有几份。
- 对话框左边列着这一格里能改的文本文件。改的如果不是入口那一份（`main.js`），存盘只算落了文件，下一轮加载时才认，刷新这一页就能看到变化。
- 对话框里的预置代码带着注释，写明能调用哪些东西、最常改的是哪三处。
- 改坏了、这一份代码加载不起来，它会照实说，再存一次或恢复出厂就行。

## 六、不写代码做一个插件

「添加插件」列表最底下一格是「用组件定制做一个新组件」。选词库、摆控件、定输出，做完就是一个真组件，Flow-Desk 挂卡和 Why Not Write 停靠都认它。Why Not Write 那边的入口在「设置 · 功能」。

- 做出来的东西住在它自己那一格 `data\plugins\<id>\`：`main.js` 是加载器读的那一份（里头就是 `export default 这张配方` 一句），`recipe.json` 是这张配方的明文，新建时补一份 `manifest.json`。界面由解释器读那份明文现长出来，从头到尾不 eval 代码。
- 界面上一共能摆十九种控件，判断逻辑能挂十八条，都有白话说明和例子，见第十六节。
- 改完点「保存」：三份直接写进这一格，写完只重载这一家，这张卡跟着变新的。不用重新构建、不用重启程序。
- 导入别人的组件、卸掉一个组件也只动这一页：改名单 → 这一家当场装上或摘掉。产物里没有插件的代码，所以没有「重编一遍」这一趟。

## 七、写代码做一个插件

一个组件就是 `data\plugins\<组件id>\` 这一格里的一份定义。加载器开机按名单一家一家把它读进来：先 import 这一格的入口文件（默认 `main.js`），拿到 `export default` 那份定义，给它做一份插件上下文、调一次 `init(ctx)`，再照说明书的 `type` 登记 —— 登记上就出现在「添加插件」列表里。不需要注册文件，不需要市场，插件代码不拼在页面产物里。

一份说明书（`manifest.json`）：

```
{
  "id": "mysheet",          // 和文件夹同名，唯一键
  "name": "我的组件",        // 列表和卡片标题上显示的字
  "author": "某某", "source": "自己写的", "version": "1.0.0",
  "host": ["fd"],           // 给谁用：fd / wnw，两家都写就是 ["fd","wnw"]
  "type": "widget",         // widget = 桌面卡片 · tool = 功能（两端） · recipe = 生成器配方
  "entry": ["main.js"],     // 加载器 import 哪一份，一颗包只有一个入口
  "order": 40,              // 列表里的先后
  "icon": "pencil",         // 图标名（icons\ 那一层里的文件名，不带后缀）
  "desc": "一句话说明",
  "dataKeys": ["counter.json"],  // 允许这个插件读写的明文文件
  "kvKeys": [],                  // 允许它用的设置键
  "appChannels": [],             // 允许它点的后台通道（见下面那串门）
  "settings": false,             // true = 卡片标题条上摆这个 ⚙ 设置
  "bank": null,                  // 自带词库时点名哪一份
  "assets": {}                   // 随包带的别的文件（脚本、插件那种）
}
```

最小例子，一个计数器（`main.js`）：

```
let P = null;                      // 插件上下文先存在这儿，init 收到以后一直用

export default {
  id: 'counter', name: '计数', minW: 2, minH: 2, def: { w: 3, h: 2 },
  init(ctx){ P = ctx; },           // 开机给一次：el / store / bus / toast / dialog 都在这一份里
  async mount(body, ctx){          // 卡片挂上来时调用，往 body 里塞 DOM
    const d = await ctx.store.loadJSON('counter.json', { n: 0 });
    const big = ctx.el('div', { style:'flex:1;display:flex;align-items:center;' +
      'justify-content:center;font-size:2.2em;font-weight:600;color:var(--text)' });
    const draw = () => { big.textContent = d.n; };
    big.onclick = () => { d.n++; ctx.store.saveJSON('counter.json', d); draw(); };
    body.appendChild(big); draw();
    return { unmount(){} };        // 撤卡、卸包时调用，监听和定时器在这儿收干净
  }
};
```

（`mount` 收到的那一份，是加载器把「这张卡自己的情况」和 `init` 那份插件上下文并好了递上来的，只用一个名字就够。那份插件上下文另外还得留着给 `expand`（⛶ 放大视图）那条路用，所以内置那几家都在模块顶上写一句 `let P = null;`。）

- 写好的这一格放进 `data\plugins\`，名单里补上它（在「添加插件」里点「装上」最省事，见第十七节），这一家就当场加载，不用重新生成页面。
- `ctx` 是唯一的一扇门：ES module 里看不见宿主的任何全局名，别想着去碰页面全局变量。它给的两半并成一份：
  - **卡片那一半**（Flow-Desk 挂卡时给）：`ctx.item` 这张卡的布局记录（id / widget / x / y / w / h）、`ctx.expanded`（面积到了页面四分之一，该给全功能了）、`ctx.layout` 与 `ctx.saveLayout()`、`ctx.setHeight(n)`、`ctx.palette`、`ctx.addDays / fmtDate / parseDate`。Why Not Write 挂功能时给的是它那一半：`ctx.where`、`ctx.ref`、`ctx.close`、`ctx.on`、`ctx.dispose`。
  - **组件那一半**（`init(ctx)` 收到、以后一直用）：`ctx.el`（建元素）、`ctx.icon`、`ctx.toast`、`ctx.copyBtn`、`ctx.bus`、`ctx.slotColor`（第几号标记色的那句 CSS，摆色用）、`ctx.slotHex`（同一颗口径回具体色号，要把颜色存进自己数据里时用，永远是一条合法色号）、`ctx.theme`、`ctx.kv`、`ctx.state`、`ctx.settings`、`ctx.store`、`ctx.bank` / `ctx.banks`、`ctx.style`、`ctx.dialog`、`ctx.cover`、`ctx.app`，加上几个不分家的小工具（`shSplit` / `phrase` / `randInt` / `pickOne` / `shuffle`）。
  - `ctx.dialog`：open(标题, 内容, 按钮行, 关闭后回哪)。第 4 个参数别漏，漏了子对话框一关人就掉回桌面。`ctx.cover`：openNode(标题, 容器, 关闭回调) —— 把你自己搭好的那一格 DOM 铺进覆盖层；另有 `setTitle(标题)`、`body()`（封面里那一格容器）、`close()`。开内核型功能就三步：建一个容器 → `ctx.cover.openNode(名字, 容器, 关闭时拆内核的回车)` → `ctx.wnw.start(容器)` 或 `ctx.rp.start(容器)`。
  - **两个内核的口**：`ctx.wnw` 是为写，`ctx.rp` 是声笔输入法练习。两边形状一模一样：`start(容器)` 开（同一个容器再点一次是拆干净重开）、`stop()` 关、`running` 现在开着没、`version` 哪一版、`available` 这一版页面里拼进了内核没有。代码就在 Flow-Desk 这一张页里，不再是一张独立的页面，组件拿不到也不用去拿任何地址。
- 门是按说明书开的，写了才给，越界当场报错：`ctx.store` 只认 `dataKeys` 点名的那几个明文文件，`ctx.kv` 和 `ctx.settings` 只认 `kvKeys` 点名的键（外加 `pack.<组件id>.` 打头的新键），`ctx.state` 只认自己组件名打头的键，`ctx.bank` 只认 `bank` 点名那份库，`ctx.app` 只开 `appChannels` 点名的方法。
- `ctx.app` 是主进程那些后台通道的口子，也有一道硬地板：装卸组件、更新程序、读写页面文件、用户数据底层、窗口控制这些通道，说明书就算点名也不发。
- 四条要守的：不往 window 上挂东西；颜色只用 `var(--…)` 现读，别写死色号；数据只走 `ctx.store`，而且是明文 json；fetch 只准指自己这一格和 `data\` 那层，别的外部地址一个都不发。

## 八、文件放在哪

- **这一页**：出厂的那份在 `Flow-Desk\pages\help.md`，跟着更新走。程序第一次开机把它拷成 `Flow-Desk\data\help.md`，之后「帮助」读的一直是 data\ 那一份 —— 更新换 `pages\` 时不会把你改过的帮助吃掉。你没动过 data\ 这一份时，更新会跟着出厂版刷新；动过就不碰，只在 `data\relocate.txt` 留一行。想回到出厂版就把 data\ 那份删掉，下次开机重新拷。
- **Flow-Desk 产物**：`Flow-Desk\pages\Flow_Desk_<版本号>.html`。里面只有外壳和共用底子 —— 插件的代码一段都不拼进来，开机由加载器从 `data\plugins\` 现读。
- **Flow-Desk 源码**：`Flow-Desk\src\_fd\src\` 是 Flow-Desk 自己的外壳模块（存储、外壳与卡片、启动卡画法与设置面板、中立工具适配、标题栏菜单、帮助装载、开机引导），`src\_shared\` 是两个程序共用的中立模块（配色、图标、字体、样式、文档、界面文字与卡片大小两份清单、词库读写、插件名单与装卸、运行时加载器），`src\_wcustom\src\` 是组件定制那一家的四份（词库底账、生成器、向导界面、内置代码编辑器 —— 改代码那个入口也在这里），再加 `src\_fd\template.html` 和 `src\_fd\build.mjs`。内置这七家组件（为写、声笔输入法练习、你的便签、你的句子、日程、音乐遥控器、组件定制）的说明书和启动卡片不在这里，它们在 `data\plugins\` 里那七个文件夹。
- **为写的源码**：`Flow-Desk\src\_wnw\src\` 那二十份模块。它有自己的出内核脚本 `src\_wnw\build-kernel.mjs`：跑一次把这一摞整段收进一层闭包，交出一份 `src\_wnw\wnw-kernel.js`；构建 Flow-Desk 那一张页时读的是这一颗产物，所以源码和产物都不进那份公开的仓库。组件定制那一颗同理，由 `src\_wcustom\build-kernel.mjs` 出 `wnw-custom-kernel.js`（这一颗不套闭包 —— 它家那些名字本来就摊在整页的顶层作用域里，套一层就得把每一处引用都改成走出口对象）。样式、字体、词库读写、名单装卸和加载器都和 Flow-Desk 共用 `src\_shared\` 那一份；音乐遥控器这一家是包，源码在 `data\plugins\`，两边加载的是同一格。
- **声笔输入法练习的源码**：`Flow-Desk\src\_build\p1.js` 到 `p6.js` 加封面底子 `src\_build\rp-base.html`，同样在构建 Flow-Desk 那一张页时由 `src\_build\rp-kernel.mjs` 收进页面的一层闭包；它的 CSS 全部改挂在 `.rp-root` 那一格容器上，递给它的 document 是容器那一份影子，所以不再需要独立页面。
- **组件自带的词库**：哪家组件自带词库，就在它的说明书里点名（`bank`）：出厂那份在包里（`data\plugins\<组件id>\bank.txt`），改过的落在 `Flow-Desk\data\<词库名>-bank\data.txt`。同一份文件，Flow-Desk 卡和 Why Not Write 停靠读的是同一格。
- **词库树形示例**：`Flow-Desk\src\tools\data-树形示例.txt`。一份能直接改着玩的样例，【大类.中类.小类】点号分层，层级不限。
- **自建词库**：`Flow-Desk\data\<词库名>\data.txt`，形状和内置那两份一样。名单记在 `data\plugins\banks.json`，名字不许重名。
- **插件**：`Flow-Desk\data\plugins\<插件 id>\` 一家一个文件夹：`manifest.json`（说明书：名字 / 作者 / 来源 / 版本 / 给哪个程序用 / 是哪一类 / 存哪些数据文件和键 / 开哪几条后台通道）、`main.js`（代码，加载器 import 的那一份）、`recipe.json`（组件定制做的配方明文，如果有）、`bank.txt`（自带的词库，如果有）、`images\`（自带的图标，如果有）。同一层还有一份 `off.json`，记的是「被卸掉的」那几家；这份名单不在，就是扫到的全都生效。
- **出厂原文**：`Flow-Desk\resources\app\data\plugins\<组件id>\`，程序自带那一层。「恢复出厂」就是从这儿把同一份文件拷回你自己那一格。
- **配方**：组件定制做出来的东西和内置那几家形状一样 —— 住在自己那一格里，`main.js` 是加载器读的那份，`recipe.json` 是配方的明文。以前那种散在 `data\plugins\` 的 `<id>.recipe.json`、`<id>.js`、`<id>.code.js` 已经并进各家的文件夹了。
- **生成库**：`Flow-Desk\data\gen-log\<组件id>.json`，每个组件各存自己历次的结果。留多少条、留多少天，在那张卡的「记录」里选。
- **两份清单**：`data\ui-text.yaml`（界面文字，见第十五节）、`data\card-size.yaml`（卡片默认大小，见第十五节）。两份都在第一次开机时由程序从自带那一层落到 `data\`，落了地就归你改。
- **用户数据详单**：`data\userdata-list.md`，「设置 · 数据」里那行「用户数据详单」读的就是它。
- **运行日志**：`Flow-Desk\data\logs\<日期>.log`，Flow-Desk 和它页面里的两个内核（为写、声笔输入法练习）写同一摞。
- **Flow-Desk 数据**：layout.json 布局、appearance.json 外观（明暗模式 / 外观模式 / 纹理 / 背景 / 圆角 / 字体 / 配色识别方案 / 标记色，合成一份）、notes.json 便签、schedule.json 日程、your-sentences.json 你的句子、settings.json 设置。外观另外吃三份明文清单：`data\palettes.yaml` 是配色库（一套色彩一段，界面上配色下拉就是它，见第十八节），`data\looks.yaml` 是外观方案库（「外观方案」那一格下拉的名单），`data\textures.yaml` 是你自己导进来的纹理名单（一张图一段，段名就是界面上「纹理」下拉里那个名字，见第十八节）；那些图本身住在 `data\textures\`。
- **程序壳**：`Flow-Desk\src\pack\main.cjs` 壳本体、`preload.cjs` 读写盘兼容层、`updater.cjs` 更新那一段、`root.json` 指向这棵树、`smtc-watcher.ps1` 是听系统播放状态的那个隐藏小进程。
- **程序产物**：根上只摆一个可执行文件：Flow-Desk.exe。为写和声笔输入法练习不再有各自的可执行文件、也不再有各自的窗口 —— 它们俩的代码拼在 Flow-Desk 那一张页里，卡片点一下是在同一个窗口的覆盖层里现开。根上那些 dll、`locales\`、`resources\` 是这一个 exe 用的一份运行时。
- **更新包**：`Flow-Desk\update\packages\`，出法见第九节。
- **发布产物**：`Flow-Desk\dist\`：`index.json` 货架清单、`plugins\<id>.zip` 逐个插件、`Flow_Desk_setup_*.exe` 首装包（里头一个插件都不带，插件各自发）。出法见第九节。
- **程序用户数据**：userdata-fd / userdata-wnw / userdata-rp（都在 `data\` 里）。IndexedDB 和 close-choice.json 在这儿；userdata-rp 里还多一份 rime-dir.json，记着指过的 Rime 目录。
- **图标**：`Flow-Desk\icons\`，见第十节。

## 九、改了源码怎么出新版

- 组件不在这一节里：`data\plugins\` 那一层的代码是开机现读、存了就是新的，改它不用出新版、不用跑构建。这一节说的是外壳（`src\`）和程序壳那部分。
- 改代码只改 `src\` 里的模块，出这一张页要分三趟：为写那二十份（`src\_wnw\src\`）跑 `node src\_wnw\build-kernel.mjs` 出一颗内核，组件定制那四份（`src\_wcustom\src\`）跑 `node src\_wcustom\build-kernel.mjs` 出另一颗，最后在 Flow-Desk 根上跑 `node src\_fd\build.mjs` —— 它读的是这两颗产物而不是源码，缺哪一颗就报错退出（确实要打一版不带那一家的，加 `--无内核` 或 `--无定制`）。只有声笔输入法练习那六份（`src\_build\p1.js`…`p6.js` 加 `rp-base.html`）还在同一趟里由 `src\_build\rp-kernel.mjs` 收进页面内部的一处闭包。构建只拼外壳、内核和共用底子，组件那一段它在构建日志里报一句「运行时加载（构建不拼段）」就完了。
- `template.html` 是骨架，不动它，所有 DOM 和样式都从 js 里注。
- build 会一段一段做语法检查，任何一段编不过就不出产物，命令行会报是哪一段。
- 版本号现拼成 `主.次.补丁-预发布名+build.<git 短哈希>`（眼下这一支是 `1.0.0-alpha+build.3f0be96` 这种形状）：`src\_build\version.json` 只记前两格（`{"shell":"1.0.0","pre":"alpha"}`），尾巴那个短哈希由 `src\_build\version.mjs` 现取 —— 给环境变量 `FD_BUILD` 就用它，没给就当场 `git rev-parse --short HEAD`，绝不写回 version.json（写了就钉死在某一笔提交上，下一笔就对不上）。从前那个每生成一次页面就自己加一的流水号已经撤了。页面文件名（`Flow_Desk_<号>.html`）、页顶那一句 `var FD_VERSION`、「关于」那页的三行号（Flow-Desk / 为写 / 声笔输入法练习，如今是同一个号）、出厂镜像里的 `package.json`、更新包和首装包的名字，全从这一处取，谁也不用再手抄那串号。顺序是硬规矩：先提交代码 → 拿到那一笔的短哈希 → 号注进去 → 再生成、再打包（反过来产物上那个号就是上一笔的）。
- exe 每次启动去 `root.json` 指的目录现找页面文件，认**最近写过的那一张**（按文件时间），不再按号的大小挑 —— 号回跳过一次（1.4.0-dev 那一支跳回 1.0.0-alpha），"挑号最大的"会一律挑回老页，屏幕上跑的是上上个版本还不报错。同一分钟落的两张才比号，比的时候先把 `+build.` 之后切掉。所以出新版不用重新打包。
- 改了 `main.cjs` / `preload.cjs` 这类程序壳的东西，才需要重新铺 exe 旁边那层：根上跑 `node src\pack\build-app.mjs`；升级了运行环境之后加 `--force` 重铺。这一趟顺带把出厂原文那层铺好 —— `data\help.md`、`data\userdata-list.md` 和 `data\ui-text.yaml`、`data\card-size.yaml` 这四份进 `resources\app\data\` 走的是真复制：链过去的话你和出厂那份就是同一个文件，你一改，出厂那一版就跟着变，第一次开机那两份原样就成了空话。整趟里只有那一张页面的内置备份副本用硬链接省地方。**插件不在这一趟里**：出厂镜像里早就没有插件那一格（程序和插件分开各自开发、各自发布），「恢复出厂」取的是 `data\plugins-factory\` 那一格 —— 它由你「导入插件」那一下自己留底，改组件想让原版跟着换新版，得回插件那一棵仓重新出包，不是跑这一趟。
- 出更新包：跑 `node src\pack\build-update.mjs`，产物在 `update\packages\`，名字是 `FlowDesk_update_<页面版本号>_<出包时间>.zip`（只带 Flow-Desk 这一个版本号，页面里已经装着两个内核）。加 `--runtime` 是连运行时一起给的整包，加 `--dry` 只报清单不落盘。
- 出发布产物：跑 `node src\pack\publish.mjs`，产物在 `dist\`，一共三样 —— `index.json` 货架清单（列着每个插件的名字 / 版本 / 作者 / 来源）、`plugins\<id>.zip` 逐个插件、`Flow_Desk_setup_*.exe` 首装自解压包。加 `--packs` 只出插件，加 `--zip` 只压整棵便携树，加 `--dry` 只报清单不落盘。**这一条现在挂着不跑**：它出的正是拿去分发的那三样，而授权那一份写的是「暂时不允许分发、修改、重新打包」，所以默认直接报错退出；看清单加 `--dry`，确实要出货加 `--照发`。
- 更新包里永远没有 `data\` 的一个字节 —— 你写的书、改过的功能模块、两份词库、帮助的工作副本都在那边；包里要是冒出一串带 data 或 userdata 的路径，程序直接拒装。
- **给用的人换版本用那一颗 exe**：`Flow_Desk_setup_<版本号>.exe` 既管首装也管覆盖升级 —— 双击它、把目录指到已有的那一棵上，点「覆盖升级」，它先把要换的旧的挪进 `update\backups\<时间戳>\`（`resources\app\` 整层挪，那一格里没有你写的东西；别的一个文件挪一份，`pages\` 只换这一个包带的那几个名，你放在那一格的稿子原地不动），再摊新的，`data\` 从头到尾不碰。那一棵正开着的时候它一个字节都不动，会让你先退干净。上面那条 zip 的本地更新是同一格落点的老路子，还在。

## 十、换图标

- 程序图标只有一张：`FD_Icon.png`，放在 `Flow-Desk\icons\`，文件名固定不能改。为写和声笔输入法练习拼在同一张页里，不再有各自的图标。
- PNG，必须是正方形，256×256 起步，512×512 更好。托盘那个 16×16 是程序自己缩的。
- 背景透明最好。不透明也行，但别留白边，Windows 会把整张方块画出来。
- 图案别太细，托盘只有 16 像素见方，细线条会糊。
- 界面里的小图标也全部外置在这一层：约九十七张 SVG，卡片图标、菜单符号、日程树的展开箭头都在里头，想用记事本改图样就改对应的 SVG。哪张图被谁引用，看同目录的 `索引.txt`，一行一个图标，写着引用它的文件和次数。
- 改完要重启程序才认。exe 旁边放一份 `icons\` 优先级更高，临时换图不用动 `resources\` 里面那份。
- 文件管理器里 exe 自身那张脸是打包时烧进去的，换它要重新打包。

## 十一、数据、备份、换机器

- 连了数据目录时是明文文件，记事本直接看直接改；没连时是浏览器 IndexedDB 的镜像。「设置 · 数据」里能看到当前是哪种后端。
- 换机器：「设置 · 数据」→ 导出全部，得到一个 json，到新机器上导入。
- 想彻底重来：删掉数据目录里那几个 json；程序版就删 `data\userdata-fd` 整个文件夹，删完就是全新首运行。
- Flow-Desk 的数据和 Rime Practice 的练习数据是分开的，Flow-Desk 不动 Rime Practice 那套。

## 十二、音乐遥控器

放歌的还是你原来那个播放器，音乐遥控器只是把它此刻的状态摆到桌面上，再给三个纯线条图标：上一首、播放或暂停（同一个按钮，停着时点下去是播，正放着点下去是停）、下一首，鼠标停上去有字。Flow-Desk 的首页卡和 Why Not Write 的停靠里是同一个控件。

- **卡片上**：歌名、艺人、谁在放，四个图标，进度条（点哪跳到哪），当前这一句。点 `⛶` 才出整页：整首歌词一行行铺开，逐字的字跟着唱到哪儿亮到哪儿，每行下面是注音和翻译。
- **三行开关**：整页顶上两个开关：注音、翻译。默认全开，各管各的那一行，关掉一个另一个照旧。
- **数据怎么来**：Windows 的 SMTC。这是系统给所有播放器开的同一个口子，凡是在任务管理器里能弹「上一首 / 下一首」浮窗的都算：Foobar2000、MusicBee、PotPlayer、Chrome 或 Edge 里的网页播放器、Spotify、网易云、QQ 音乐，一律认。程序起一个隐藏的 PowerShell 小进程在那头听着，播放器一动它就把手报上来，不是一秒问一次的问法。进度条在两次手报之间自己按倍速数，只有数得明显对不上（差过 0.5 秒）才回头要一次实情。
- **指定播放器**：默认的认法是「谁在放就认谁」。但远程桌面、浏览器后台标签页这些也会算成一个会话，偶尔会认错人。音乐遥控器自己的齿轮设置（卡片标题条上的 `⚙`，Why Not Write 停靠的标题条上同名那颗）里点定一个，此后只报它；它此刻没开，卡上照实说是它没开，不偷偷换别人。选的其实只是 `%LOCALAPPDATA%\Flow-Desk\players\pin.txt` 里的一行明文，Why Not Write 停靠读的是同一个值，两边不会各说各话。
- **音乐文件夹**：同一个齿轮设置里的「音乐文件夹」那一行，程序里弹系统那个选文件夹的框，选完写成一行明文 `%LOCALAPPDATA%\Flow-Desk\players\musicdir.txt`。Flow-Desk 卡和 Why Not Write 停靠读同一行，指一次两边都认，整页顶上那个「选一个文件夹」按钮也是同一个值。这一行清空，就退回只认播放器报上来的那个文件旁边的同名歌词。
- **子文件夹**：歌常按歌手、专辑分了一层又一层，只扫顶层等于没扫。指了目录就往下穿透着找，最深 6 层、总共 8000 个文件封顶；同一首歌的同名歌词有几份时，取浅层那一份。
- **歌词的挑法**：顺序是：内嵌 ttml、同目录同名 ttml、内嵌逐字 lrc、同目录同名逐字 lrc、内嵌增强 lrc、同目录同名增强 lrc、内嵌逐行 lrc、同目录同名逐行 lrc。手动选的歌词文件永远算数，排在所有自动规则前面。「同目录同名」这一路认的是播放器报上来的那个文件旁边的目录，没指音乐目录也认。
- **是不是歌词**：不看后缀，闻三下就知道：开头跳过 BOM 和空白，出现 `<?xml` 或 `<tt` 当 TTML；第一行是 [分:秒.毫秒] 这种时间戳当 LRC；都不是当纯文本，整页看全文，卡上会说「没有时间戳」。
- **逐字、增强怎么分**：看一句里打点密不密：一句被拆出三段以上算逐字，只拆一两段的算增强，整句只有一个时间的就是逐行。
- **内嵌歌词**：不整份读，按字节区间把歌词那一段抠出来。一首 7 MB 的 mp3，实际读进来十二万字节左右。
- **MusicBee**：它本体不往系统的媒体控件写东西，得给它装一个插件。关掉 MusicBee，在音乐遥控器的整页里点「装插件」，或者自己把 `data\plugins\music-remote\mb_FlowDesk.dll` 拷到 `<MusicBee>\Plugins\` 里（同名就覆盖），再开 MusicBee。它做了什么写在 `%LOCALAPPDATA%\Flow-Desk\players\bridge.log` 里；同一目录下 `musicbee.txt` 是正在放的文件路径，音乐遥控器就靠它找同目录的歌词。
- **本地开发那一页上**：那台服务器后面没有主进程，系统播放状态这条通道就不存在，拿不到 SMTC。那时候手动选一个音频文件，选完照样能放、照样读它的内嵌歌词，进度条走的是文件自己报的时间。没有会话时卡上会照实写「系统里此刻没有正在放的歌，播一首就有了」；「指定播放器」和「监听插件」那两行在这种页面上根本不出现，没有这条口子就不摆这一行。

读不到歌词的这几种情况，界面上会照实说是哪一种，不会闷着：

- m4a、mp4、mkv、webm 的歌词常常装在内嵌字幕轨里，这种轨不读。在同目录放一份同名的 .ttml 或 .lrc 就行。
- 从流媒体下载下来的 m4a 不少是 FairPlay 加密的，里面的东西读不出来，也是照实说。
- 普通标签里的是读的：mp3 的 USLT 和 SYLT，flac 和 ogg 的 TTMLLYRIC、LYRICS、UNSYNCEDLYRICS（同名标签里谁排在前面用谁），m4a 的 ©lyr，mkv 和 webm 的 Tags。flac 和 ogg 想放整份 TTML，字段名建议写 TTMLLYRIC，光写在 LYRICS 里也读。

## 十三、Why Not Write：卡片之间的关联、追踪、出场次数、写作热力图

- **关联怎么建**：卡片里加一个属性，「填写方式」选成**关联**。往后每加一行就是「谁 → 谁」：挑一张目标卡，勾它算哪一档（人物关系 / 从属关系 / 资源持有），写关系名（师徒、辖下、持有……随你写），再给起始和结束两个时间。起始和结束两处都能空着，空着就是那一处不限时间；两处都空 = 一直有效。
- **追踪是第五种填写方式**：属性那一行的「填写方式」选成**追踪**，这一格顶上就摆进度条（勾了几条 / 一共几条，当场数出来，不许手填），下面一条一行待办。每条待办能挂多张卡片、也能挂多段正文；卡片删掉了，挂在它上面的那条不会跟着消失，只在名字处写「（卡片已删）」。右栏「追踪」分区列的是所有选了追踪属性的属性项，一行都不欠。
- **转移方式**：一行关联还能写它是怎么来的：自始持有、继承、赠予、转让、抢夺、丢失、拾得、继任、销毁，这九个词点一下就填进去，也照样能手写别的。
- **三张图**：左边那条图标栏上「关联」点开就是三张：**关系图**、**从属图**、**资源盘点**。读的都是同一批关联行，只是各看各的那一档。从属图按「A 属于 B 就把 A 挂在 B 底下」排成树，没有上级的当根；资源盘点按东西分组，分成「当前谁拿着」和「历代」两段。
- **时间读法**：每张图顶上三档，和白板那条时间轨用的是同一套算法：**拟真**（写真日期，比如 2026-06-01）、**架空**（按历法数，写 3年5月1日；历法预设和白板共用那一份，不选就是 12 月 / 每月 30 天）、**原点**（离零点多少天）。
- **查看时间**：读完法再填一个时间点：起始在它之前、结束不在它之后的那条才算「有效」。没到的灰着标「未到」，过了的标「已过」，用另一套历法记的标「另一套时间」，起止都没写的永远算有效。这一格空着 = 不限时间，全都算。三张图共用这一份读法，在任意一张上换，另外两张跟着换。右上角那个按钮管「只看这本书」还是「所有书 + 公共卡一起看」。
- **响应度三档**：名字一出现就自动亮（高）／出现时先问一句，点了才亮（中）／只亮手动「关联设定并高亮」的那几处（低）。选哪一档，卡片上那句浅色说明就跟着换。
- **出场次数**：高响应的卡固定算 1，不给调；中响应数的是你在多少章上点过「亮」；低响应数的是这张卡挂了多少条关联。中、低各带一个全局权重，默认 1，能调 0.1 到 1，步进 0.1 —— 改权重只是重新换算，不把那些章重扫一遍。数字在两处都显示：左栏卡片列表每一行后面，和卡片池里。跨书看的时候，不是这本书的卡给一个「—」。
- **写作热力图**：右侧「写作统计」停靠里。年是一张一列一周的图，月是七天一行的日历格，顶上切。深浅按五个维度各自归一再加权合起来：字数、段落数、章节数、设定条数、灵感条数，默认各占 20%，五个权重自己调。鼠标停在格子上，一行白话写出那天这五项各是多少。
- **热力图这些数是怎么来的**：照实说：段落数是从这一版起按前后差值记的，章节数、设定条数、灵感条数看的是条目的创建时间。所以这份文档之前的那些天，只有字数那一项有值，其余四项是空的，不会替你编出来。

## 十四、Why Not Write：白板上的卡名、两条评级，书架上的两种标记

- **节点上的卡名**：白板节点在属性里选了哪张卡片，节点上就多写一行「▣ 卡名」。卡改名，节点跟着改 —— 不是定时去问，是卡一有变动就重画。
- **空白网页记访问历史**：编辑窗里那一档「空白网页」会把真落地的网址记成一份历史，历史里能收藏、收藏里能置顶；同一页跳到不同小节（地址只有 # 后面那段不一样）算同一条，不刷屏。历史和收藏全局一份，不分标签格，顶上那排按钮里的「访问历史」点开就是那张列表，点一条就在开着列表的那一格打开。
- **标签右键多五条关闭**：在标签条上右键，分屏两条下面一道分隔线，接着是「关闭当前标签」，再看凑不凑得出来：左边有标签才给「关闭左侧标签」，右边有才给「关闭右侧标签」，不止一枚时给「关闭其他标签」和「关闭所有标签」—— 凑不出来的那条整个不摆，不是摆着点不动。只管右键这一格，别的格子不动。
- **两条评级**：时间评级和事件评级各管各的，不叠加：时间评级管时间线上谁先谁后，事件评级管事件序号那一套。两条都是数值小的在上、大的在下，没填的按默认层级摆。
- **书架的标记**：两种：正在标签页里开着的那几本有一道边框；当前切过去看着的那本边框走强调色、粗一点。网格和列表两种视图的标记一样，第三本没开的书什么标记都没有。

## 十五、设置：界面文字清单 · 卡片大小清单 · 快捷键这一档 · Ctrl+S · 悬停看全文 · 切档不闪 · 用户数据详单

这一节里两份清单是同一套做法：都是 YAML 明文（用缩进和冒号排版的纯文本），记事本、Notepad++ 都能直接打开改，存盘保持 UTF-8；「设置 · 数据」里那一行三个按钮 —— **重新读一遍**、**把改动写进程序**、**在这里改**。界面上不显示文件路径，也没有「打开清单」那个按钮：想在外头改就用 Notepad++ 打开 `Flow-Desk\data\` 里那一份，程序读到的是同一个文件。第一次开机时这两份由程序从自带那一层（`resources\app\data\`）落到 `data\`，落地之后这一份就归你，程序不再覆盖它。

- **界面文字清单**（`data\ui-text.yaml`）：按「哪个程序 · 哪一页」分段，段里一行一个地方 —— 冒号左边是界面上原来那句话，右边写你要的字。入口在设置 · 数据这一档的「界面文字」那一行。同一个字在不同页就是两段底下的两行，各换各的，互不影响。右边空着、或者写得跟左边一样，都算没改。改完存盘，界面上那一句立刻跟着变，不用重启。
- **卡片大小清单**（`data\card-size.yaml`）：一张卡片两行 —— 「出厂」那一行是源码现在给的大小，只当参照；「你要」那一行写你要的大小，都是「宽 × 高」的格子数。入口就在「界面文字」那一行底下的「卡片大小」。改完存盘就认：新摆到桌上的卡片按新大小；你从来没亲手拉过大小的卡片也跟着变，亲手拉过的不动。「其他卡片」这一张是不在这份清单上的卡片共用的底子。为什么出厂那一行也要写进文件：程序得留着「这张卡原来多大」才对得上「你亲手拉过没有」，所以两张栏都摆在磁盘上，而不是只记你改的那一栏。
- **「在这里改」**：点下去直接在设置里开一个编辑框改这份清单，打开时光标停在清单开头，不用自己滚。
- **「把改动写进程序」做什么**：按下去先给你看一份改动清单（哪句改成哪句、在源码的哪几个位置），你确认了才落笔：写进源码并重新生成页面，以后这份文件就算删掉，程序里的字和大小也是新的。办完会弹窗问一句：「立刻重启」还是「稍后手动重启」—— 立刻就把 Flow-Desk 整个重开一遍，所有窗口、菜单和托盘一次换成新的；选稍后就先干活，回头自己关一次再开也一样。窗口关闭时如果编辑框里有没存盘的改动，会先问一句「还有未保存的内容，是否保存后再关闭」。
- **旧「提示语」页呢**：已经删掉了。第一次开机时它里面改过的句子会自动搬进界面文字清单（搬了几句会当场报一句），改字只走清单这一个口子。按钮、标签、菜单栏那 19 条、托盘那 4 条也都在这份清单里。
- **改一句会动到哪些地方**：三类走同一份清单：**弹出来的短句**、**鼠标悬停的说明**、**输入框里的灰字提示**。生成页面时从共用模块、功能包、主进程这些代码里一次全收，同一个字符串在几个地方出现过就一起收进同一行。
- **带数字的那些句子**：源码里是拼接的短句收成**模板**，变量位置写成 `{1}` `{2}`，比如「一共 {1} 项」。改的时候可以把 `{1}` 挪到你想放的位置，也可以干脆不写（那个数就不显示）；写了清单里没有的序号（比如 `{9}`）当空处理。
- **Rime Practice（照实说）**：Flow-Desk、为写、声笔输入法练习读的都是磁盘上那一份界面文字清单，产物里不再各带一份副本；但声笔输入法练习的设置没有分档标签，也没有清单编辑入口，所以它没有「界面文字」「快捷键」这些档，改字要到 Flow-Desk 或 Why Not Write 的设置里改。不支持的地方不摆空架子。
- **快捷键这一档**：设置里的「快捷键」把窗口里能用的键列全了，每个键都写了 Windows 的 `Ctrl` 和 macOS 的 `⌘` 两种写法。最后一句提醒：**请注意避免快捷键冲突。** 程序不主动查冲突 —— 查一遍得把 Flow-Desk、为写、声笔输入法练习三套键位都常驻着比对，白占内存也白占时间。
- **Ctrl+S 管什么**：所有该保存的地方默认都认这个键：**保存当前这一层**。从你光标所在的地方往上找第一个摆着「保存」按钮的容器（便签、日程这些卡片、Why Not Write 的浮层和面板都算一层），替你把它按下去。这一层没有「保存」时才往上退一层（对话框、覆盖层）；上一层自己接了这个键（编辑器里的 Ctrl+S）就不抢它的；按钮上写的不是「保存」两个字（比如「保存到别处」）也不乱按。输入法正在拼字的时候不接，不会把你还没上屏的字吞掉。
- **字被框子切掉了**：该显示全的文案不为了省事压短，框子也不为了塞下而拉长 —— 装不下还是省略号收着，**鼠标停上去给你原生提示看全文**。这事挂在页面上一处统一处理，凡是真被切掉的才有提示，没切掉的不多嘴，自己写过说明的地方不覆盖。
- **Why Not Write 右栏停靠的顺序**：右栏停了几张面板时，每个标签左边那道小把手**按住就能拖上下顺序**，松手就换好，按书本记 —— 换一本书回到那本书自己那套顺序。Flow-Desk 这边卡片本来就是网格上随便摆的，两边各按各自的形态，不硬套。
- **设置切档不再闪**：根子两处：一是以前每切一次把左边那一列竖标签也重建一遍（整屏白一下），二是「程序」「数据」这两档的内容是异步问出来的 —— 先画一版猜的，答案回来再改一版。现在标签那一列开面板时只建一次，切档只换右栏；异步那两档把上回问到的先摆在原地，字没变就不回写。
- **用户数据详单**：设置 · 数据 那一档里一行「用户数据详单」，点开是一篇明文文档（`data\userdata-list.md`），写的是**不受软件更新影响的那些东西都存在哪儿**。每一次点开都现读，你改完那份文件保存再点就是新的；读不到时照实说文件在哪儿，不另备一份替代内容。Flow-Desk 的「帮助」旁边和 Why Not Write 左侧图标栏上各有一个同样的入口。

## 十六、组件定制：十九种控件和十八条判断逻辑

组件定制（见第六节）的界面一共能摆十九种控件，生成结果前能挂十八条判断逻辑。每一格都带着白话说明，这一节把话再摆全一遍，配着例子。除控件本身以外这一节还有四小节：**这一格的填写要求**（格下红字）、**界面怎么摆**（一行并列、成组、组循环、分页签）、**结果出成三档**（列表组合、表格、文本组合）、**取值怎么挂名字**。

### 十九种控件

- **二级下拉**：一个或几个分类并成一套选项。比如把「性别」「年龄档」两个分类的词摆进同一个下拉。
- **三级联动下拉**：先选大类，再选大类底下的项。选了「人物」，第二格只剩人物底下的。
- **穿透下拉**：这一类连它底下所有子类的词条一起列出来。选「饮食」，底下「主食」「菜」「饮品」的全在一格里。
- **融合/联动下拉**：词库分类、别处切出来的字段、写死几项，并成一套选项。三路来源一个下拉。
- **文本提取计数**：按分隔符切字段，顺手数出几段。粘贴「甲、乙、丙」，切出三个词，还数出「3」。
- **数字指定**：中间手打，右边 +1、+10 两个按钮。改份数用这个。
- **数字展示**：把别处的数字摆在这儿看。比如把上面「文本提取计数」数出来的 3 亮出来。
- **文本输入**：自己打，原样进结果。
- **可修改随机**：文本框带一个随机按钮：点一下从指定分类抽一个，抽完还能手改。
- **开关**：点一下在开/关（或你自己填的两个词）之间翻；这个数还能当份数。
- **滑杆**：一根能拖的数：原创度、差异度这种就该长这样。
- **区间随机数**：给两个数随机出一个整数，可带单位；界面上留空的话，生成时每一格自动掷一次。
- **生成式下拉**：下拉里有什么，由上游那个变量现下是什么决定。点了「男」，「称号」里只剩男的那批。
- **格式模板**：拼接格式本身当一批词条来抽：先抽一个格式，再往里填内容。比如抽「{身份}·{名号}」还是「{名号}的{身份}」。
- **多选勾选**：从指定的几个分类里摆出一列勾选框，自己勾几个算几项。勾中的这几项并进一格进结果，还能当份数（勾了 3 个就跑 3 轮）、也能交给「每条字数上下限」数。
- **整段文本**：一整段原样进结果，不切字段也不数段。填背景、写设定这种用这个——要切字段是「文本提取计数」的活。
- **输入即筛**：打几个字，下面只留含这几个字的候选，点一条就填进框里。词库分类有几百条、翻着累的时候用这个代替下拉。
- **颜色**：色块和色号文本框互相跟着改，动色块文本框跟着变，反过来也成立。进结果的是文本框里那一串，色号（`#3b6cb5`）或色名（`砖红`）都成——想拿色名就把词库那一格填上「名,色号」两列。
- **日期时刻**：原生的日期 / 时刻输入框，选一档。「2026-10-04」这种串在数算逻辑里读出来就是年份 `2026`，能直接拿去算年龄、算相差几天。

### 这一格的填写要求

每一个控件底下都带一块「填写要求」，写的是**这一格现下填着什么合不合格**（跟抽出来什么词无关，也跟这一格怎么取值无关 —— 换了功能，这几项还留着）。八项都能不填，不填就是不比：

- **必填**：选「要」之后，这一格空着就在那一格下面出「这一格还没填」。
- **字数最少 / 字数最多**：数的是去掉空格的字数。
- **数字不小 / 数字不大**：从这一格里捞出第一个数来比，`18级` 和 `18` 一样。
- **写法**：整串要符合的正则写法，前后自动加锚，比如 `\d{4}-\d{2}`；写坏了当不合格。
- **不合格时**：这一档定松紧。**拦住这一轮**（默认）—— 有不合格的就先不出结果，提示语里把哪几格、各卡在哪儿说明白；**只提一句，照样出** —— 那一格下面照样写着哪儿不对（字色换成警告色，跟拦住的那种红字分开），结果照出。勾中「必填」这一格一般就该拦住，这一档主要给字数、写法那种「不太对但能用」的要求。
- **不合格时说**：这一项填了，那句话就说你这一句；留空就说引擎那句白话（比如「字数超过 4，现在 7」）。

那行字只在按过生成之后出 —— 界面刚打开那一下不主动标；你回头把那一格改合格了，那行字自己消失。

### 十八条判断逻辑

判断逻辑排在生成之后、出结果之前，按下面这个先后顺序过一遍：格式改写 → 一样的只留一条 → 搭配限制 → 相似程度 → 字数上下限 → 多样化 → 打乱顺序 → 标序号 → 收条数。「不合格先重抽」排在这整趟之前；「条件分支」和后面几条各管各的位置。

组件定制界面上这十八条分两组摆在链子底下：**剔掉不合格的**是五条 —— 一样的只留一条、每条字数上下限、相似程度、搭配限制、多样化，这五条在流水线里会让路给「不合格先重抽」，重抽到位了就不必把它们剔掉；剩下十三条管的是出不出、出几条、怎么排、内容怎么改。分组名单只写在引擎那一头（`src\_shared\sh-gen.js` 里的 `GEN_SOFT`），界面上不另抄一份，引擎那头的名单一改，界面上这两组跟着改。

- **随机抽的词不重复**：同一轮里随机抽到的词不再抽第二遍，那一摞抽干了才允许重样。
- **空着的不进结果**：没填值的项不出那一行。
- **整块空了连名字一起不出**：一块里一条都没出，就别只甩个光标题。
- **一样的只留一条**：同一个词重复命中，只留头一条。
- **不合格先重抽**：别的判断只会把不合格的行剔掉，剔一条就少一条；这一条是剔之前先重抽：按行名找到产生它的那个控件或组循环，重新取一次值（随机那一档真的再抽一遍），最多试若干次。合不合格照配方里摆着且开着的这几条问：空着的不进结果、一样的只留一条、每条字数上下限。
- **条件分支**：只做决定，不碰取值：读一个变量现下是什么，从上往下找第一条成立的（命中就停，末尾不填条件的那条算否则），这一条给的决定谁要用谁自己来取 —— 改分类由抽词那一头取，换拼法由拼结果那一头取，不要哪几格 / 换条数 / 插一行排在整条判断流水线最后做。结论还能挂在这个块起的名字上，文本模板里 `{那个名字}` 就取得到。比法一共十四档，填条件时先选哪一档，再填要比的东西（提示那一句会跟着这一档换）：文字六档是**和它一样 / 和它不一样 / 里面含这几个字 / 里面不出现这几个字 / 整串一模一样（空格不算）/ 整串符合一个正则写法**；数字四档是**等于几 / 不小于几 / 不大于几 / 在哪个区间**（从这一格里捞出第一个数来比，`18级` 和 `18` 一样，填区间写成 `18,30`）；长短四档是**字数正好几 / 至少几 / 最多几 / 字数在哪个区间**（数的是去掉空格的字数）。正则那一档整串匹配，前后自动加锚，写法照 `\d{4}-\d{2}` 这样来；正则写坏了就当这一条不成立，不会把生成卡住。
- **最多出几条**：结果再多也按这个条数收住。
- **每条字数上下限**：少于下限的丢掉，超过上限的裁掉，0 表示不管这一头。
- **每条前面标序号**：像【方案1】【第1环节】那样给每条编号，`{序}` 是第几条。
- **出完打乱顺序**：结果顺序不跟着界面排。
- **有空的就不出，提示哪个没填**：少一项就不生成，免得出一半。
- **按权重抽**：词库里词条前面写「4|玄铁」「0.02|传说」这样的数加竖线就是权重：数越大越常见，不写算 1。开了这条，随机那一档按权重抽，结果里只留词本身，「4|」这一小截不会跟着进结果。
- **数算逻辑**：按公式算一个数：加减乘除取余、括号，`min`（两个数取小的）、`max`、`abs`、`round`、`floor`、`ceil` 都能写；变量用花括号点名，像「价格 = {基准价} × {数量} × min({等级},3)」这样。算出来的数挂在你起的名字上：模板里 `{那个名字}` 取得到，组循环的「份数跟着」、数字展示的「看哪个数」也认它。
- **搭配限制**：说清比哪两格、怎么比：完全同名 / 一个含另一个 / 前一个的尾字等于后一个的首字 / 汉字字组有重合。撞上了整条这一轮不算成 —— 开着「不合格先重抽」的话会当场重抽。
- **相似程度**：「一样的只留一条」只认完全一样；这一条认「太像」：两行有超过几成的汉字字组相同（相邻两字算一个字组）就只留一条。再绑一本词库分类（比如 28 个真实城市名），撞上班上现实词的也剔掉。
- **多样化**：一次出 N 条，两两比较有几项不同，只留不同够数的组合。和「按权重抽」「最多出几条」不冲突，排在它们前头挑。
- **生成格式改写**：抽完还要动内容：剥掉括号里的字、色号换成黑、颜色太浅换黑、英文连着重复的两三个字母去掉、首字母转大小写、按「旧=>新」替换表改字、只留数字。动作可以叠好几个，按列表顺序来。
- **多维定义**：几个维度互相定义：词库词条写成「K1 温带」这种编码加词，规则表一行一条像「土壤：气候 K1 = S1」（想要什么用冒号，给什么是等号后头的，条件写「维度名 空格 编码」）；界面上只填了两个维度，剩下的照表递归推，推不出走那一维的「推不出就报」那句。结果挂在你起的名字上；勾「摊组合」就把能配的全组合一行一条摊开，交给「多样化」挑差异够大的。

### 界面怎么摆

功能模块添好了是一格一格竖着排的，想换个摆法，用「加块」那一排的结构块 —— 顶上能给的是控件、一行并列、成组、分页签、纯文本、组循环六个按钮，往里套时能装什么由这一块自己定（并列行和组里只放控件，组循环放控件和成组，分页签放一页一页）。

- **一行并列**：几个控件挤同一行，不各占一整行。开关、数字指定这种小格子并排放就用它。
- **成组**：几格打包成一块，外面套一个框、给一个组名。这一栏还多一个「怎么摆」三档可选：**一直摊着**（默认，和从前一样）、**可以收起**（组名右边一个箭头，点一下收起）、**打开就收着**（初次生成时是收起态，要看要点开）。**收起不等于不算**：收着的组里那些格照样取值、照样进结果，界面上只是不摊开。
- **组循环**：按一个数出几份，每份是同一摊控件。份数吃上面哪个变量、每一份套什么模板，都在这块里填。
- **分页签**：几页各摆一摊控件，页签上写这一页叫什么。切换只看得到当前那一页，**没在当前页里的格子照样取值、照样进结果**。一页都还没加时，界面上就不摆这一排页签。
- **纯文本**：界面上摆的一句死字，不进结果。

每一块右边都有「复制代码」，点一下把这一块的配方明文拷走，贴到右边「源码」那一栏改，也能贴给另一个组件。

### 结果出成三档

「输出」那一块的「出法」有三档：

- **列表组合**：按文本模板拼，一项一行，结果是「几条」，复制全部就是模板拼出来的那一份。这一档每条右边多一个「只换这个」，只重掷产生这一行的那一格。
- **表格**：一行一格摊成表头加格子，标题上写的是「几行几列」。下面一排色块点谁、谁就进表并且排在前面，一个都不点就按界面上的顺序全摆出来。这一档的「复制全部」给的是**制表符分隔**的那一份，贴进 Excel 或 WPS 就是一张对齐的表。整张表一次摆出，没有「一行对一格」的说法，所以这一档不摆「只换这个」。列太多时表格自己横向滚，不会把结果区撑破。
- **文本组合**：整块一段自由文本，可以勾「拆成多行」把这一段切进行流水线，交给「多样化」「最多出几条」按行处理。

### 取值怎么挂名字

- 每个控件和每条判断逻辑都能起个**名头**；名头就是取值的门牌 ——「份数跟着」和「数字展示」认它，文本模板里 `{名头}` 也认它。
- 输出区可以「拆成多行」：一行一条摆进结果，再交给「多样化」「最多出几条」这一头按行处理；不拆就是整块一段。
- 「只换这个」：配方改了两处以上时，可以只把眼下这一处换进正在用的那份，其余不动。

### 用到库里没有的功能模块 / 判断逻辑

上面那十九种控件和十八条判断逻辑写在代码里，就是「库」。一份组件里引用了库里没有的名字（比如配方里写着 `fn:'tree'`，可库里没有这个功能模块），程序不会硬凑一个假东西出来 —— 它在这四个地方各扫一遍：导入别人给的配方、在组件定制里存这一家、改代码存这一家、导入一个功能包。扫到了就问一句要不要提取。

- **提取进的是清单，不是库**：勾上的每一条记进 `data\lib-pending.json`，存着名字、界面上叫什么、功能描述、它在这份组件里带的那一段参数（或者代码原文那一小段），还有它在哪儿出现。这份清单只是待办记录，程序不会拿清单里的代码去跑。
- **查看入口**：功能模块和判断逻辑两块标题右边各摆着「待实现 N 条 · 查看」和「导入」两个按钮。打开能逐条改名字和功能描述、删掉这一条、复制这一条、整份复制走、存成文件，也能把别处那份清单读进来并进去（同一个名字已经有的不动，免得盖掉你填过的描述）。Flow-Desk 和 Why Not Write 里看的是同一份清单。
- **拿这份文件交给 AI 写实现**：「复制全部（交给 AI）」出来的那份文本，每条都带着名字、功能描述、参数和代码原文，抬头写明实现往 `src\_shared\sh-gen.js` 里写、要在 `src\_shared\sh-wizard.js` 那几张表登记，改完 `src\` 要重新生成页面才看得见。
- **实现进了代码之后再导入**：回到这一块点「导入」，库里已经能跑的那几条就摆进可选名单，新建组件时选得到。实现还没进代码的，点导入只照实告诉你「导进来也跑不起来」，不会摆进可选名单。

## 十七、插件的装卸与发布

外壳是一副空骨架，功能全在 `data\plugins\` 的插件里。一家一个文件夹：`manifest.json` 是说明书（名字 / 作者 / 来源 / 版本 / 给哪个程序用 / 是哪一类 / 存哪些数据文件和键 / 开哪几条后台通道 / 自带哪份词库），`main.js` 是代码，`bank.txt`、`images\` 是这家自带的词库和图标。「你的便签」「日程」「音乐遥控器」这六家内置功能，出厂时就是这样六个文件夹，和导入的第三方包走同一条通道。

- **卸掉改的是一份名单**：`data\plugins\off.json`，记的是「被卸掉的」那几家。名字在里面的那一家，开机就不读它 —— 加载器不 import 它，桌上一张卡、设置里它垫的那几行跟着一起消失。包本身永远留在 `data\plugins\` 里，随时装得回来。这份名单不在，就是扫到的全都生效。
- **丢进去就生效**：往 `data\plugins\` 里放一个插件文件夹（或者一个 `.zip`，程序开机自己摊成文件夹），重启 Flow-Desk 就加载它，不用在界面里点一次「装上」。这一条和上一条是同一件事的两面：认的是「这一格里有什么」，不是「名单里写了什么」。
- **两步连着一趟**：改名单 → 这一页当场刷新（顶上进度条一步一步报，装上的那家直接加载进来）。Flow-Desk 的「添加插件」列表和 Why Not Write 的「＋ 打开内容」列表两边都能装卸，入口对等；插件自己的设置在它自己的齿轮对话框里，程序设置里不再替它摆一页。
- **卸掉时的勾选项**：确认框里明说「包留在原地、随时装回」；数据默认留着。只有勾了「同步清除数据」，这份包自己点名的那几份明文和它占的那几个键才一起清。
- **导入**：一条口子两种形状都收 —— 压好的 .zip（别人传给你的成品包），或者解开的文件夹（本地开发、两台机器之间拷图纸）。落点是 `data\plugins\`，存进去一律摊开成文件夹（zip 只是运输形状）；同名已经在那儿就退回不动，不悄悄盖掉你原有的包。装完当场加载这一家。把 zip 摊开这一趟走的是 Flow-Desk 程序那条通道，本地开发那一页上点它会照实告诉你这一步做不了。
- **改代码是同一格文件**：卡上的 `✎` 和本地开发那台服务器上的 `/_comp` 写的是同一个文件，不会出现「那一份是草稿、这一份才作数」。改完存了就是新的，见第五节。
- **发布给别人**：在 Flow-Desk 根上跑 `node src\pack\publish.mjs`，`dist\` 里出三样：`index.json` 货架清单（每个插件的名字 / 版本 / 作者 / 来源都列着）、`plugins\<id>.zip` 逐个插件、`Flow_Desk_setup_*.exe` 首装自解压包。别人拿到 zip 走「导入」，拿到 setup 解开就是一棵完整的树。加 `--packs` 只出插件，加 `--dry` 只报清单不落盘。

## 十八、界面为什么是这个颜色：配色原则与背景层次

这一节讲两件事：一套色彩进了界面要站住哪几处；背景想从纯色换成渐变或图片时按什么规矩。里面写的数都是程序现在真在算的（配色引擎在 `src\_shared\sh-color.js`，外观层在 `src\_shared\sh-look.js`），不是设想。

### 「设置 · 外观」那一屏上有什么

从上往下分七组，每组一行小标题：**明暗**（跟随系统 / 按一日内时间切换 / 手动设置）→ **方案**（外观方案那一格下拉 + 「删除当前」、字体、改完没存时那一行「覆盖 / 另存 / 撤销」）→ **卡面**（外观模式、卡片圆角、控件圆角、卡片间距）→ **纹理**（下拉与强度，连着「导入一张纹理图」，挑中自己导的那一张时再多一颗「从名单里划掉」，还有那张图「一张占几 × 几格」）→ **背景**（纯色 / 渐变 / 普通图片 / 四方连续，另有两根模糊滑杆、压暗提亮、「照当前壁纸重取一遍配色」）→ **渐变**（渐变怎么画那一档和它的调节控件，这一组没东西时整组不摆）→ **配色库**（配色下拉 + 「随机换一套」、标记色、整摊库）。七组之下还有一颗「恢复出厂取值」：只把这一套方案里的卡片圆角、控件圆角、纹理强度回到出厂那一档，配色、方案名、外观模式、纹理、字体和方案清单本身一概不动。

- **一套外观方案 = 配色 + 外观模式 + 纹理 + 字体 + 圆角**，存在 `data\looks.yaml` 里，挑中一条连它带的配色一起换过去。改完没存就在方案之间跳，会先问你这一笔是丢掉、另存还是覆盖。
- **背景、卡片间距、标记色这三样不进方案**：换方案不动它们。标记色也不进配色库，它自己一份，只有你在那一格里改才变。
- **配色库存的是色号**（`data\palettes.yaml`），界面吃的整套颜色由它现推；这两份都是明文，改完存盘当场跟着变，不用重启。
- **外观模式只管边框、阴影、边界线、发光**这四件事，分四档：质感（不画边框，靠一层环境影加一层投影分高低）、辉光（一圈霓虹描边加外发光；浅色底只画那圈描边，发光和光晕不画，会糊成一片）、纯平（一道细边框圈出卡片和控件，层次只靠底色深浅分）、无界（什么都不画，只留一根几乎看不见的分隔线）。卡片底只有实色这一档。

### 一套色彩要站住的三处

界面上一共三十来个位置有颜色，全部由你给的那几条色号推出来，界面上没有第二套写死的颜色。推得到推不到，判断只看三处：

- **页面底**：整张桌面的颜色。它决定这套算明亮还是黑暗，也决定卡片往哪个方向推才看得见。
- **正文**：卡片上的字。这条决定一套色彩能不能用 —— 无障碍给普通小字的下限是 4.5，Flow-Desk 自己往里收到 4.6。
- **强调**：选中的那一个、按钮、焦点框、进度条用的颜色。它在自己站的那块面上要够 3.0。

这三处是说法，程序里真拦的是五道（数值自检 `node src\_fd\look-check.mjs` 报的就是这五道）：正文 ≥ 4.5、次级文字 ≥ 4.5、强调 ≥ 3.0、控件描边 ≥ 3.0，再加一条不比对比度的 —— 卡面和页面底的明度要差 4~28 个点。差不到 4 个点卡片和页面糊成一片，超过 28 个点两层就像各摆各的纸。那四道对比量的都是真实压在字底下那一块面（卡面掺了 20% 墨之后的颜色），不是配色库里那颗没掺墨的卡面。

**卡面和次强调是加分项，不是硬条件。** 只给两三条色号时，程序自己把卡面派生出来（往白混、往黑压，或者从底到墨那条线上插一档），次强调用主强调转个色相凑出来。

### 给几条色号，界面上就定住几个角色

按默认那套识别方案（甲 · 语义认领）：

- **一条**：只定页面底，其余全派生。能用，但"强调"会显得平淡。
- **两条**：底 + 强调。这是能出成品的一套，正文由卡面现推。
- **三条**：第三条够"中性"（饱和度不超过 0.55、和页面底对比不到 2）就被认成卡面，不满足就跳过。
- **四条**：第四条被认成正文。到这儿，上面那三处全部由你给的色号占住，程序不再猜。
- **五条**：第五条是次强调，同时占住组件色位里的第二个位置。一套色彩到这一档已经能给整套界面供色。
- **六条、七条**：甲这一档没有角色可派，它们只出现在生效色值那张表上。想让每条都给的颜色都被用上，五到六条正好；给到七条以上就是浪费，给到一条两条也能开，只是"强调"和"正文"变成程序替你挑。

### 明亮和黑暗各自怎么配

- **明亮**：一条近白带点色相的当底（`#f3f4f6`），一条中性深色当正文（`#2f3338`），一条中等饱和的当强调（`#3b6cb5`），卡面可以另外给一条比底更白的（`#ffffff`）。内置明亮那套就是这么四个数。
- **黑暗**：给一条深底，但**别给纯黑**（`#1b1d22` 这种带一点色相的深灰就行）—— 整屏底色在黑暗这一路只往亮推一点点，从不往黑压，一压就把这套色彩的色相丢了。卡面比页面底亮一档，输入框反过来压黑。正文给白色系的深灰（`#e6e8ec`）比纯白耐看。
- 两件要避开的：**别给浅灰当正文**（次级文字的深浅由程序按"这块面上还能撑到 4.5 的最大掺入量"现算，人给的浅灰读不动）；**卡面别给比页面底深太多的**（深过一截，一开桌面就看见一块补丁，程序会跳过这种色号自己派生）。

### 明亮还是黑暗，是算出来的

拿识别出来的页面底和正文各算一次 WCAG 相对亮度，比个高低：字比底亮算黑暗，字比底暗算明亮。两个数挨得太近（差不到 0.02）就**不下结论**，这套色彩会被对比下限拦下来。为什么不用"底色自己的亮度对不对得上一个门槛"：那一法在中明度的底上会猜反，卡面被往白里混、字被推深，看着就是灰扑扑一片。

界面上「设置 · 外观」最上面那一格是另一件事：整套界面此刻按黑暗还是明亮走（跟随系统 / 按一日内时间切换 / 手动设置三档），它挑的是配色库里标着对应明暗的那几套，不改上面那条判定口径。

### 四套识别方案：同一堆色号，认法不一样

- **甲 · 语义认领**（默认）：按饱和度、明度认领四个角色，卡面掺墨走卡面自己那个色相、暗一档。手上一套"看得出意图"的色彩用它。
- **乙 · 明度排序**：最亮当底、第二亮当卡面、最暗当正文，中间最艳的当强调，全程不看饱和度。规则最短，代价是浅底那几套里第二亮的那条常常正是强调色。
- **丙 · 双锚插值**：只认最亮（底）和最暗（墨）两个锚，带彩度的一律降级成点缀，卡面不从你给的色号里取，由"底 → 墨"那条线上插到差 4~28 个明度点那一档。色号给得乱、又不想让某一条颜色染满屏时用它。
- **丁 · 输入法老口径**：照声笔输入法练习从前那一份认领法子（浅底卡面混 62% 白、深底混 5% 白），下限和推法保留它自己的数，是"逐色复现那一份"的对照案。

用哪一套记在外观存档里（`data\appearance.json` 的 `look.scheme`），开机读回来，默认甲；界面上没有摆这一处切换的入口，要换就在自己机器上改那一格。

### 背景那一档：纯色 / 渐变 / 图片

- **纯色**：整张桌面一个颜色。
- **渐变**：现在是一条写死的斜向三色（150°，页面底混强调 → 页面底混黑白 → 卡面）。它三个停靠点全取自这套色彩自己派生的色号，所以永远不会跑出色相之外的颜色 —— 这一点保留。
- **图片**：挑一张整张铺满（`cover`），上面再压一层极淡的调子（深底压 6% 黑、浅底提 14% 白）救"图片太亮或太暗"。图片句柄存在程序自己那一格里，换机器要重新挑。

渐变这一条只该是五档里的**一档**，现在被当成唯一形状套给了所有配色。按"有几个带彩度的锚、色相跨多远、卡面和页面底差几个明度点"这三件事分五型跑过 57 套配色（从 Rime 皮肤读进来、这两天整批撤进备份的那 55 套 + 内置 2 套），落点是：强调牵引 17 套（30%）、同族二档线性 14 套（25%）、明度微渐 14 套（25%）、双色相径向 8 套（14%）、弥散 3 套（5%）、不给渐变 1 套（2%）。**现在这一条只对三成合适**，剩下七成要么被拉出一条它们根本不需要的色相带，要么该散成团却排成了一条直线。五档是：

- **明度微渐**：只有一颗带彩度的锚（明月、碧水、Steam、YouTube、墨池这类）。只往明暗走，一点不引入新色相，明度跨度上限 6 个点 —— 拉过头页面底自己变成主角，卡片反而看不出边界。
- **同族二档线性**：两颗彩色、色相不到 30°（DOTA 2、瓷青、冰渊、桃雾、雾汐这类，其中四套的色相跨度实测就是 0°）。两端就够：页面底 → 页面底混主强调 6~10%。三档渐变在它们身上会多出一个"中间是谁"的疑问。
- **强调牵引**：三颗带彩度（青柠、潮焰、藍精靈），或两颗且色相跨到 30~60°（内置那两套、銅鑼衛門、NBA）。就是现在界面上那一条，终点收到卡面色，卡片像是从背景里浮出来的。
- **双色相径向**：色相跨到 60° 以上（安卓 130°、暗堂 132°、胡蘿菔 148°、清風 120°）。这种排成一条直线就成了彩虹带，改成从某个角往外散的光，圆心放在卡片密的那一角，第二个色相族只许出现在中间那一档、掺入量不超过 8%。
- **弥散**：四个锚全部带彩度（琥珀竹烟、青天、梦中国度）。没有哪一条线能同时装下它们，只能散成 3~4 团大半径柔色斑；团色只从主强调、次强调、五个色位里取，不新造。写死三条：最多四团、每团直径不超过视宽 45%、两团中心之间不少于视宽 25% —— 这不是审美，是让卡片挪动时背景不会跟着变成一团脏。

五档共同两条硬规矩：每一个停靠点只能取自已派生的色号，**不许新造第四颗颜色**；渐变不许把这套色彩的明暗结论翻面（自检里按 16×9 网格采样，任一点把结论翻到另一头就判这组渐变不通过）。有了渐变之后，"卡面和背景的明度差"要按**每张卡片正下方那一点**量，不按全图平均；某张卡在自己那一点上差不到 4 个点，推那张卡的卡面，不改整屏渐变。正文级文字必须坐在实色卡面上（卡片现在一律实色不透底，渐变碰不到它），允许直接压在渐变或壁纸上的只有卡片外面空处的小字和卡片标题条上的字，且按那一段里最深那一点复检 4.5，不许用文字描边或外发光救对比。

**上面这些渐变分档、按脚下那一点量明度差，还有下面那两根模糊滑杆，都还没进代码**，现在界面上还是同一条斜向渐变。

### 纹理和壁纸各管各的，别混

纹理（纸质、布质那一沓平铺小图）铺在**卡片表面、控件底下**，强度顶格是 40 —— 那是把每张纹理图的像素全算进去量的天花板：强度 40 时字底下最暗和最亮两个像素上的对比还剩 4.57~5.13，全过；到 60 就有六张纹理跌破 4.5。纹理不许铺进控件（分段槽、输入框、按钮那几块面上不铺）。

内置那十一张之外可以自己导：在「设置 · 外观」的纹理那一格点「导入一张纹理图」，挑一张 PNG / JPG / WEBP，收下后它进「纹理」下拉里「自己导入」那一组，卡片当场就铺上。导进来的图和那份名单各住各的 —— 图落在 `data\textures\`，名字落在 `data\textures.yaml`，名单是明文，改完存盘当场跟着变，不用重启。

导入只做**简单格式测试**，不是「无缝认证」：边长得在 8~1024 像素之间、文件不超过 4MB，然后把四条边缘隔一个点比一遍（左边和右边、上边和下边），RGB 平均差在 16 以内算接合得上。判不过、或者压根测不出来的，对话框会照实说一句「这张图多半贴不开，照样收吗？」，你回「我知道，照样收」它照样收下 —— 这一条不硬拦，因为接合得好不好，最终得看它在卡片上贴出来什么样。名字撞了内置那十一张里的某一个（比如又导一张也叫「亚麻」的），界面上的名字会自动让位成「亚麻 2」，物理文件各留各的。那颗「从名单里划掉」只从名单里删这一段，`data\textures\` 里那张图不跟着删。

壁纸在**卡片底下**。卡片实色不透，所以壁纸、渐变、图片模糊都碰不到卡片上的字，两边的数各算各的，不叠加、也不互相顶。

图片壁纸的模糊程度定稿这样（同样还没进代码）：

- **普通图片**：0~24 像素，滑杆行程给满画幅。只糊壁纸那一层，不许对卡片做；糊之前把那一层往四周各放大 8px（或缩放到 106%），免得窗口边缘出现一圈没底色。糊完要重算一次"等效底"（按 16×9 网格取平均），拿它复核卡面和脚下那一点的明度差、以及压在壁纸上的那两类文字的对比 —— 这个数不改配色，只用来验收。哪一条不满足，界面上就把"再糊一点"这条路留着（糊正是解决"图片太花、字读不动"的手段），而不是拦着不让调。
- **四方连续**（一张无缝小图反复贴）：0~6 像素。到 6 以上图案自己就化开了，反复贴的意义就是看得出那个纹样，糊过 6px 等于把它变成一张没花纹的底，那就该去用普通图片那一档。做法是对**已经平铺好的那一整层**糊，不是一格一格糊完再拼；糊完露出缝说明这张图本来就不无缝，那是导入那一步该拦的事。格宽另有一档可调（25%~200%），和模糊是两个各管各的滑杆。
